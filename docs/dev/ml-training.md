# Модели под вузы и кампусы

Базовые модели работают для всех вузов сразу. Когда у вуза накапливаются свои данные, ML-платформа
`doomich-ml` (каталог `ml/`) обучает модели **под конкретный вуз** (LoRA для LLM, распознавание речи,
эмбеддинги) и **под конкретный кампус** (навигация по фото), проверяет качество и кладёт версию в
реестр моделей. Сервисы подхватывают активную версию сами, без перезапуска.

## Реестр моделей

```
registry/<вуз или _global>/<тип>/<область>/versions/<версия>/manifest.json + файлы модели
registry/<вуз или _global>/<тип>/<область>/active.json      ← указатель на активную версию
```

| Тип (`kind`) | Область (`scope`) | Кто использует | Что даёт вузу |
|---|---|---|---|
| `llm_lora` | `default` | vLLM (подключает адаптер на лету) | лексика, подразделения, принятые сокращения, тон ответов |
| `asr` | `default` | сервис ASR | термины дисциплин, фамилии преподавателей, акустика аудиторий |
| `embeddings` | `default` | API (поиск по документам) | точнее находит нужные фрагменты в документах вуза |
| `vpr` | slug кампуса | сервис навигации | «Где я?» по фото в корпусах этого кампуса |
| `wakeword` | `default` | приложения (скачивают модель) | слово «Думыч»; обычно одна общая модель `_global` |

Если у вуза нет своей версии, используется `_global` (кроме LoRA: без адаптера работает базовая модель).
Версии переключаются в панели администратора («Модели») или командой
`doomich-ml registry activate <вуз> <тип> <версия> [--scope <кампус>]`; откат — активация прежней версии.

## Как обучать

Всё описывается одним TOML-файлом на вуз — пример с комментариями: [`ml/configs/example.toml`](../../ml/configs/example.toml).
Каждая секция необязательна: включайте то, для чего уже есть данные.

```bash
# на GPU-узле, в контейнере с CUDA и доступом к реестру
docker compose -f infra/compose/compose.yaml -f infra/compose/compose.gpu.yaml run --rm ml \
  doomich-ml build /datasets/hse/models.toml --registry /registry --runs /runs
```

`build` обучает модели по очереди, считает метрики на отложенной части данных, сравнивает с
порогами из `[gates]` и регистрирует версию. Прошедшие пороги версии активируются сразу
(`--no-activate` — только зарегистрировать), остальные остаются в реестре для разбора.
Данные лежат в `infra/compose/datasets` (каталог `/datasets` в контейнере), журналы и промежуточные
результаты — в `infra/compose/runs`.

Отдельные шаги можно запускать и по одному: `doomich-ml wakeword|vpr|llm|asr|embed ... --help`.

## Данные по типам моделей

### LoRA для LLM (`[llm_lora]`)

JSONL с чат-примерами: `{"messages": [{"role": "system"|"user"|"assistant", "content": "..."}]}`.
Собирается из FAQ вуза и синтетических вопросов по документам, которые генерирует «учительская» LLM:

```bash
doomich-ml llm prepare --out data/hse/chat.jsonl --university "НИУ ВШЭ" \
  --faq data/hse/faq.jsonl \                      # {"question": ..., "answer": ...}
  --docs data/hse/docs --llm-url http://vllm-llm:8000/v1 --llm-model doomich-llm
```

Факты (сроки, правила, адреса) адаптер не «запоминает» надёжно — они должны приходить из базы знаний
вуза через поиск (раздел «База знаний» в панели). Адаптер учит форме и словарю. Базовая модель в
конфиге должна совпадать с той, что обслуживает vLLM (`LLM_MODEL_ID`).

### Распознавание речи (`[asr]`)

JSONL: `{"audio": "путь/к/файлу.wav", "text": "выверенная расшифровка"}` — отдельно обучающая и
проверочная выборки. Используйте только записи, на которые есть согласие (например, лекции, которые
преподаватель разрешил использовать). Метрика — WER до и после дообучения.

Без обучения тоже можно помочь распознаванию: `doomich-ml asr glossary --docs <каталог> --out glossary.txt`
соберёт термины вуза для исправления расшифровки моделью.

### Эмбеддинги (`[embeddings]`)

JSONL с парами «вопрос → фрагмент»: из FAQ и сгенерированные учительской LLM по фрагментам документов
(`doomich-ml embed synth --chunks chunks.jsonl --out pairs.jsonl --llm-url ... --llm-model ...`).
Метрики — Recall@1/5 и MRR. **После активации новой модели эмбеддингов документы вуза нужно
переиндексировать**: каждый фрагмент хранит имя модели, которой он векторизован, и поиск идёт только по
совпадающей.

### Навигация по фото (`[vpr.<кампус>]`)

```
campus-main/
  photos/<ключ узла графа>/*.jpg    # 8 кадров по кругу в каждом узле, днём и вечером; угол — …_h090.jpg
  nodes.json                         # {"<ключ узла>": {"name": "...", "floor": 3, "building": "А", "tags": [...]}}
```

Ключи узлов — те же, что в [графе кампуса](campus-graph.md). Дескриптор (DINOv2) дообучается
метрическим обучением на фото кампуса, качество — Recall@1/5 на отложенных кадрах, результат —
дескриптор в ONNX и индекс эталонных снимков. Область версии — slug кампуса.

### Слово активации (`[wakeword]`)

```
wakeword/
  pos/ neg/          # синтез: doomich-ml wakeword synth --out wakeword --voice ru-default ...
  recordings/        # записи добровольцев (с согласия), WAV 16 кГц
noise/               # фоновые шумы аудиторий и коридоров
```

Метрики — доля пропусков (FRR) и ложных срабатываний в час. Модель маленькая (≈60 тыс. параметров),
работает на устройстве; звук не отправляется на сервер до срабатывания.

## Пороги качества

```toml
[gates.vpr]
recall_at_1 = [">=", 0.85]

[gates.wakeword]
frr = ["<=", 0.05]
false_alarms_per_hour = ["<=", 0.5]
```

Метрики каждой версии видны в панели администратора рядом с версией. Версию, не прошедшую пороги,
можно активировать вручную, если понятно почему (например, проверочная выборка была слишком мала).

## Пошаговое обучение и регистрация

Шаги можно запускать по одному (`doomich-ml asr train ...`, `doomich-ml vpr train ...` и т. д.) — каждый
пишет каталог запуска в `--runs` с файлами модели, `config.json` и `metrics.json`. Такой запуск
регистрируется отдельно, с той же проверкой порогов:

```bash
doomich-ml register runs/asr-2027-03-01 --kind asr --tenant hse --activate
doomich-ml register runs/vpr-main-2027-03-01 --kind vpr --tenant hse --scope main --activate
```

Без `--activate` версия только появляется в реестре; `--force` активирует её, даже если метрики ниже порогов.
